# Cryptography

Resilient Messenger uses OpenMLS 0.9.0 for RFC 9420 group state and messages. It does not implement a custom ratchet and does not use libsignal. The selected suite is `MLS_128_DHKEMX25519_CHACHA20POLY1305_SHA256_Ed25519`. OpenMLS `content-debug` and `crypto-debug` features are disabled.

Each 1:1 conversation is an MLS group containing devices from two accounts; each group chat contains every member device. A BasicCredential encodes a version, 16-byte device ID, 32-byte account/root fingerprint and 16-byte device-certificate fingerprint. The application validates that binding against the Account Root Key-signed Device Certificate before accepting a member.

`CryptoEngine` provides KeyPackage generation/export, group create/join, application encrypt/process, add/remove proposal and commit, self-update, encrypted state export/import, epoch/member inspection, credential verification and local destruction. State export authenticates and encrypts the provider store and signer with XChaCha20-Poly1305 under a 32-byte local state key; raw OpenMLS state never crosses UniFFI.

The Rust test suite covers 1:1 exchange/reply, 10/100-member groups, add/remove, removed-member rejection, replay/duplicate/out-of-order/loss tolerance and encrypted restart persistence. Host UniFFI tests call the same engine. CI separately gates generated Swift/Kotlin calls and XCFramework/AAR builds because upstream builds but does not runtime-test iOS/Android targets.

Measured artifacts are in `PROTOCOL_BUDGETS.md` and generated by `just crypto-size`. These tests and measurements do not establish that the system is secure. Independent external audit and real-device review are mandatory before mass launch.
