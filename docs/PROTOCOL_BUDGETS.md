# Protocol budgets

Canonical CBOR is the binary wire format; JSON is prohibited on the wire. v1 uses only RFC 8949 canonical definite-length arrays, unsigned integer tags and byte strings: no maps, no indefinite values, no floats and no tags. This makes the byte representation deterministic and rejects duplicate map keys by rejecting maps altogether.

Limits: frame 64 KiB; encrypted text event 4 KiB; receipt batch 50; default envelope TTL 604800 seconds. Steady-state short content targets <=512 application bytes and emits a hard warning above 1024 bytes. MLS Welcome/Commit are measured outside this budget. Gzip/zstd are never automatic for small messages; a future negotiation may enable compression only if its complete encoded frame is smaller.

Version negotiation: a client proposes exactly one major v1 in `ClientHello`; a server accepts v1 or returns `Error(UnsupportedVersion)`. Unknown frame/application tags are rejected in v1. Future compatible fields require a new schema array version, never ignored map fields. Every sync cursor is monotonic per account/device and cursor regression returns `CursorRegression`. Upload deduplication is keyed by `(account_id, device_id, client_message_id)`; replay returns `Replay`, and a previously accepted idempotent upload returns the original acceptance rather than duplicating delivery.
